## 原始任务清单（依赖顺序）

以下验收标准保留为原始需求定义；当前完成状态以“最终验收状态”表为准。

### TASK-01：定义版本化评估报告契约

**类型**：AFK  
**阻塞于**：无——可立即开始  
**覆盖**：US-01、US-02、US-05

#### 要构建什么

建立版本化 JSON 作为正式评估的权威格式，并让现有测试执行能够产出最小可用的报告。报告为每个稳定测试标识记录结果分类、简短脱敏摘要、测试套件版本、运行时和驱动来源信息；Markdown/HTML 只能由 JSON 派生。

#### 验收标准

- [ ] 定义并校验版本化 JSON 报告格式，包含稳定测试 ID、通过/失败/跳过/环境错误等结果，以及测试套件、JDK、数据库、驱动和适配包来源信息。
- [ ] 报告中不包含密码、令牌、完整 JDBC URL、主机名、端口、数据库名或用户名。
- [ ] 现有至少一个测试类可端到端生成 JSON 和由其派生的 Markdown 报告。
- [ ] 报告格式有自动化测试，阻止不兼容字段变化。

### TASK-02：引入稳定 JDBC 测试标识与标准结果分类

**类型**：AFK  
**阻塞于**：TASK-01  
**覆盖**：US-01、US-02、US-05

#### 要构建什么

为现有 JDBC 测试分配永久稳定 ID，并把执行结果归一为兼容性失败、能力跳过、已知差异、环境/执行错误、适配包不完整和清理失败等可比较的分类。重命名 Java 类或方法不得改变报告身份。

#### 验收标准

- [ ] 现有测试用例都有唯一稳定 ID，报告不以 Java 类名或方法名作为主键。
- [ ] 兼容性失败与环境/执行错误在报告和退出状态中可区分。
- [ ] 声明能力跳过与已知差异不被计为兼容性失败。
- [ ] 自动化测试证明实现重构后的稳定 ID 仍可与历史报告比较。

### TASK-03：支持本地声明式数据库适配包

**类型**：AFK  
**阻塞于**：TASK-01、TASK-02  
**覆盖**：US-01、US-03、US-05

#### 要构建什么

交付本地适配包发现、加载和结构校验能力，使用户可显式选择一个本地包运行测试，而不再要求在 Java 核心中新增数据库枚举。适配包至少声明身份、版本范围、能力、测试资产、命名空间策略和最小权限。

#### 验收标准

- [ ] 用户可通过显式本地路径选择适配包，且不修改 Java 核心代码。
- [ ] 适配包缺少任一 JDBC 测试区域的资产或能力声明时，运行前报告“适配包不完整”并阻断。
- [ ] 本地适配包生成的报告始终标为本地/试验性，不能作为正式基线。
- [ ] 提供一个最小示例适配包和自动化结构校验测试。

### TASK-04：交付安全测试命名空间预检与生命周期

**类型**：AFK  
**阻塞于**：TASK-03  
**覆盖**：US-01、US-03

#### 要构建什么

让一次评估只能使用专用 Test Namespace。运行前校验适配范围和最小权限；未指定时创建唯一命名空间，运行后仅清理该命名空间。禁止回退到业务 schema 或基于表名前缀的隔离。

#### 验收标准

- [ ] 适配包可声明命名空间创建、使用和清理策略，以及最小权限。
- [ ] 未确认破坏性操作、无法创建/使用命名空间或权限不足时，用例执行前终止并说明原因。
- [ ] 运行产生的对象仅存在于本次 Test Namespace；成功后仅删除该命名空间。
- [ ] 清理失败被单独记录为阻断结果，保留定位信息，且不会扩大删除范围。

### TASK-05：交付零依赖 Python `init` 安全配置流程

**类型**：AFK  
**阻塞于**：TASK-03  
**覆盖**：US-01、US-03、US-04

#### 要构建什么

提供标准库 Python `init` 命令，交互式选择可用适配包并生成 Secure Local Configuration。配置默认引用环境变量密码、声明测试命名空间破坏性操作同意项，并被版本控制忽略。

#### 验收标准

- [ ] `init` 不依赖第三方 Python 包，可生成可供后续运行使用的本地配置。
- [ ] 生成配置不保存明文密码，使用环境变量引用。
- [ ] 生成配置默认不会被 Git 跟踪，并包含显式破坏性操作同意项。
- [ ] 用户可在 Linux、macOS、Windows 上完成该流程，路径处理不依赖 Unix shell。

### TASK-06：交付 Python `run` 的完整安全评估路径

**类型**：AFK  
**阻塞于**：TASK-04、TASK-05  
**覆盖**：US-01、US-04

#### 要构建什么

提供 Python `run` 命令，将依赖预检、驱动校验、适配范围校验、命名空间生命周期、JDBC 测试执行和 TASK-01 报告串成一次可运行的用户路径。Maven 仍可作为等价高级入口。

#### 验收标准

- [ ] `run` 检查 Python、JDK 21、Maven，缺失时输出中英文、可复制的安装指引且不自动安装软件。
- [ ] 仅接受固定 Maven 坐标或本地 JAR 作为驱动来源，并在报告中记录 JAR SHA-256。
- [ ] 实际数据库/驱动超出适配范围时默认阻断；显式试验性覆盖的报告不可作为正式基线。
- [ ] 对一个本地适配包，用户可通过单条 `run` 命令得到脱敏 JSON 和 Markdown 报告及本地诊断日志。

### TASK-07：交付基线比较与 CI 门禁

**类型**：AFK  
**阻塞于**：TASK-06  
**覆盖**：US-02、US-04

#### 要构建什么

提供 Python `compare`，比较当前评估与用户认可的基线评估，并将新引入的兼容性失败、跳过或已知差异逐项列出。让 `run`/`compare` 使用确定的退出码供 Maven 和 Python CI 流程调用。

#### 验收标准

- [ ] 同一测试套件版本的两份报告可按稳定测试 ID 比较，并输出新增变化清单。
- [ ] 测试套件版本不同的报告拒绝作正式回归判断，并提示需重新建立基线。
- [ ] 新增兼容性失败、环境/执行错误、适配包不完整、预检失败、清理失败返回非零退出码。
- [ ] 声明能力跳过和正式已知差异不阻断 CI；本地覆盖和试验性运行不能作为正式比较依据。

### TASK-08：补齐 JDBC 核心接口测试与能力门控

**类型**：AFK  
**阻塞于**：TASK-02、TASK-03、TASK-06  
**覆盖**：US-01、US-03、US-05

#### 要构建什么

将连接、事务、Statement、PreparedStatement、ResultSet 和元数据等核心接口纳入统一的稳定 ID、结果分类和适配包能力门控，审计现有测试资产以确保各测试区域均显式声明。

#### 验收标准

- [ ] 每个核心 JDBC 接口区域都在适配包清单中有明确资产和能力声明。
- [ ] 缺失声明会触发“适配包不完整”，而不是隐式跳过。
- [ ] 核心接口用例的通过、失败、环境错误能够在正式报告中按稳定 ID 追溯。
- [ ] 对至少一个官方适配包运行核心接口测试并产生完整结果矩阵。

### TASK-09：补齐 JDBC 可选接口与标准类型矩阵

**类型**：AFK  
**阻塞于**：TASK-08  
**覆盖**：US-01、US-03、US-05

#### 要构建什么

将 CallableStatement、RowSet、LOB、SQLXML、高级类型及 ARRAY、SQLXML、ROWID、REF、STRUCT 等纳入显式的能力与类型覆盖矩阵，确保不支持的能力以声明跳过呈现而非失败。

#### 验收标准

- [ ] 每个可选接口和标准类型都具有稳定测试 ID、能力声明和报告结果。
- [ ] 可选能力被适配包明确关闭时，报告显示能力跳过并包含理由。
- [ ] 适配包缺失可选测试资产或能力声明时，运行阻断为“适配包不完整”。
- [ ] 报告以接口和标准类型显示 Outcome Matrix，不生成单一兼容性百分比分数。

### TASK-10：实现可审计的已知差异治理

**类型**：AFK  
**阻塞于**：TASK-02、TASK-03、TASK-07  
**覆盖**：US-02、US-05

#### 要构建什么

让适配包可登记 Known Difference Record，并在报告与比较中区分审核后的正式差异与本地覆盖。记录必须可验证、版本受限且有复审期限，防止把回归伪装成已知差异。

#### 验收标准

- [ ] 每条已知差异都要求稳定测试 ID、数据库/驱动版本范围、原因、外部链接和复审期限。
- [ ] 缺少任一必填信息的已知差异在适配包校验中失败。
- [ ] 正式已知差异和本地覆盖在报告中有不同信任标记。
- [ ] 过期、范围不匹配或本地的已知差异不能静默掩盖正式回归。
